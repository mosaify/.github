# Contributing to Mosaify

Thanks for helping make software security more actionable.

1. Check existing issues and discussions before opening a new one.
2. For substantial changes, open an issue to align on scope first.
3. Keep changes focused, document user-visible behavior, and include tests where applicable.
4. Avoid including secrets, tokens, customer data, or sensitive vulnerability details in commits or public issues.
5. Describe the problem solved and how the change was validated in your pull request.

Individual repositories may have additional development instructions; those take precedence.
